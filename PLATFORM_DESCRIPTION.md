Я собрал для каждого запроса пул объявлений из нескольких источников: поиск по словам заголовка, по частям слов, по описанию, по истории выборов для похожих запросов и смысловой поиск по заголовкам. Потом LightGBM Ranker выбирает из этого пула 50 объявлений. Он учитывает оценки каждого источника, фильтры, подкатегорию, локацию, расстояние и признаки объявления. Смысловая модель работает локально; её веса приложены к коду.

Для проверки разделял данные по тексту запроса: одинаковые формулировки не попадали одновременно в обучение и проверку. На dev Recall@50 составил 0,8922, на control — 0,8662. Control уже просматривался при разработке, поэтому это ориентир, а не оценка скрытого теста.

В ошибках чаще всего встречались разные окончания и опечатки, нужная услуга только в описании, а также смысловые совпадения без общих слов. Для них добавил поиск по частям слов, признаки описания и смысловой поиск. Перед отправкой проверил все 2452 строки `answer.csv`: в каждой ровно 50 разных объявлений, все `query_id` и `item_id` в исходном строковом формате и присутствуют в данных.

Запуск и зависимости описаны в `README.md` архива с кодом. Команда воспроизведения: `python final_solution.py --data data --output answer.csv`. Архив содержит локальные веса модели и готовый ответ; исходные Parquet-файлы берутся из задания.
